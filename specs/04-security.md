# 04 — Security

Deterministic stops at every boundary; probabilistic layers operate only inside them. Threat model: assume workers get hijacked — intake is adversary-writable text by construction. Design target: a fully compromised worker can write bad *content* through audited, reversible syscalls — and nothing else.

## Identity & privilege map

| Actor | OS user | DB role | Clearance | Can |
|---|---|---|---|---|
| Sam (interactive build) | `sam` | `claudio_core` | 2 (BYPASSRLS not used; explicit 2) | DDL, migrations, inner-circle writes, purge, approve |
| Panel | `claudio` (service) | `claudio_panel` | 2 | approve/reject, merge_people, asserted links, life-plane writes via L1 |
| Each worker | `claudio` (service) | `w_<component>` (inherits `claudio_agent`, NOLOGIN base) | per-component (`ALTER ROLE w_x SET claudio.clearance = 'n'`) | EXECUTE L1, SELECT views — nothing else |

- `claudio_agent` base: `EXECUTE` on `l1.*`, `SELECT` on granted views. **No table grants, no DDL, no role management.** Verified by the red-team suite, not assumed.
- Per-worker roles give true audit attribution (`created_by = current_user`) and per-worker clearance. Provisioning a component creates its role (a `requires_core` step — by design: granting capability is always a human act).
- Clearance is set via `ALTER ROLE … SET` (superuser-only), read by RLS policies via `current_setting('claudio.clearance')`. A worker cannot raise its own.

## Filesystem & process

- `core/` — owned `sam:staff`, mode `755`: workers read, cannot write. `custom/`, `wiki/`, `memory/`, `archive/` — group-writable by `claudio`.
- Git hook (pre-commit, repo-level) rejects commits touching `core/` from the `claudio` user. Tripwire pipe: `git status` over `core/` + permission audit every hour; any drift ⇒ alert.
- launchd plists under `/Library/LaunchDaemons/com.claudio.*` owned by root/sam — generated by the applier from the registry; **a worker cannot edit its own launch config or settings file** (tool allowlists live in core-owned per-worker settings).
- Secrets in macOS Keychain under the `sam` login keychain for core; worker-needed secrets injected per-plist as env from a core-owned, `claudio`-unreadable store rendered at plist-generation time. The core DB password never exists in any `claudio`-readable file.
- FileVault on. Backups encrypted (restic). Backup retention 90 days — bounded so purges actually expire (below).

## Network egress (closes exfiltration)

macOS `pf` anchor: default-deny outbound for the `claudio` user; allowlist = Anthropic API, approved connector hosts (Google APIs, Slack), plus per-tool additions approved with the tool. Loaded at boot from a core-owned anchor file. A hijacked worker that can read has nowhere to send.

## The boundary rules

1. **No write outside L1** — grants (above).
2. **No read above clearance** — RLS on every life-plane table; sensitivity defaults: row inherits `max(adapter default, role.default_sensitivity)`; writers may raise, never lower.
3. **Text never escalates privilege.** Inner-circle crossings (approve, merge_people, asserted links, core proposals, DDL) require `claudio_panel`/`claudio_core` — reachable only by a human act on the panel or a core session. No string in any context window can synthesize the credential.
4. **No agent sends.** Outbound credentials exist only in the notifier (destination hardwired to Sam) and in approved sender pipes whose sole input is `status='approved'` proposals — a transition only rule 3 actors can cause. Drafts to third parties always stop at a proposal.
5. **Lethal trifecta forbidden.** No worker combines untrusted input + sensitive read + external channel. The filer (dirtiest input): clearance 1, no network tools, L1-only. The orchestrator (untrusted input + reads): no send tools — its outbound is `propose`. Enforced by per-worker tool allowlists + pf, not by prompt.
6. **Taint visibility.** Proposal payloads carry `quoted` — verbatim untrusted content the panel renders visibly as foreign text.
7. **Rate limits** in every L1 write (02) — deterministic blast-radius ceiling + anomaly alert at 3× baseline reads.
8. **Kill switch** — `claudio-stop`: `launchctl bootout` of every `com.claudio.*` job + panel banner. Core-owned script; drilled quarterly (an untested kill switch is the backup-never-restored problem).

## Sensitivity & privacy

- Tiers: 0 normal · 1 sensitive (pastoral matters, others' confidences, relationship judgments) · 2 restricted (future: finance, medical).
- **Stewardship**: third parties never consented — minimize (pointers over mirrors), default-by-context (church role ⇒ 1), sensitive rows excluded from general packets by RLS, not by hope.
- **Wiki gap (known, accepted for v0):** wiki files are readable by all workers (one OS user). Rule: **files carry sensitivity ≤ 1; restricted content lives only in DB rows** (RLS-protected), referenced from pages by id without content. Lint scans pages for leak patterns. Upgrade path: per-clearance OS groups on wiki subdirs. (questions-queue #2)
- **Purge** (real deletion vs append-only): `purge()` core-only; deletes row + links + doc references, logs the *fact* to audit. Wiki: page edit + `git filter-repo` procedure documented for the rare full-scrub. Backups age out at 90 days ⇒ purge becomes complete within the retention window.
- **Model boundary:** every packet leaves the device at inference. Provider: Anthropic API (no-training/retention terms — re-verify annually). Restricted rows never reach any model context except a clearance-2 session explicitly invoked by Sam.

## Standing verification

- **Red-team suite** (pipe, weekly + on every migration): connect as `w_test` (agent-standard) and assert the negative space — cannot `CREATE TABLE`; cannot `INSERT` into tables directly; cannot `UPDATE messages.status` to approved; cannot read sensitivity-2 rows at clearance 1; cannot write `core/`; cannot read core secrets; cannot modify own plist; egress to a non-allowlisted host fails. Every new grant/function/stop ships with its negative test. Suite red ⇒ alert, and the applier refuses new component provisioning until green.
- **Tripwire** + **watchdog** (03) cover integrity and liveness. Quarterly: kill-switch drill, restore-from-backup drill.
