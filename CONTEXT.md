# CONTEXT.md

Read this plus `specs/00`–`07` and you know everything that matters. `specs/` is the law; this file is the reasoning, history, and taste behind it. Written for a future agent with zero conversation history.

## What claudio is

A self-describing relational scaffold of one person's life — the **life-harness for his agents**. It ingests every data stream (windows), distills raw into atoms and a biography wiki, serves context as the API (`get_context` packets), aligns everything against a user-authored purpose contract, and maintains itself. It is the context layer, never the harness: external agents (Claude Code, Agent SDK, Hermes-class assistants) are consumers to feed, not competitors to rebuild. The bet: agents, models, and harnesses churn every few months; a clean data model of a life, with its contracts, lasts decades. Own the data, rent the agents.

The apex idea — and the part of this project that is genuinely novel — is **life purpose as a typecheck against reality**: a user-maintained contract (goals, values/beliefs, attributes, a priorities document) that the whole recorded life is continuously checked against. Everything else is downstream plumbing the ecosystem will increasingly commoditize; the purpose contract and the owned scaffold are the durable core. Build order front-loads them.

## The reasoning behind the load-bearing decisions

- **The decay test** governs everything: a brand-new agent, given only this repo and the database, must orient and operate correctly in one session. Self-description (COMMENT ON with examples, generated SCHEMA.md with sample rows, this file) is how the system survives tool churn.
- **L1 as syscalls**: agents hold zero direct table writes; SECURITY DEFINER functions validate, clamp, audit. Raw SQL as an agent write surface fails in practice (21% solve rates, injection incidents — research). Reads are SELECT over invoker views under RLS.
- **Atoms** are units of life experience — compact index cards (summary ≤750, detail, verbatim quotes, refs), never documents. Tier ladder: raw (stays at source) → atoms → rollups. Depth scales by destination, not atom size. Record everything non-spam (recording ≠ extracting; a meme-filled family chat day is one honest line that powers the relationship record); extract conservatively. Bias toward thoughtful larger chunks.
- **Importance is structural, never volumetric, and headlines are computed, not chosen.** Sam's deepest recurring concern is LLM taste interrupting human taste ("the LLM thinks X is the most important thing today, so everything is about X"). The defenses: user-set role weights order sections; due-dates order obligations; `notable` is a closed-reason-vocabulary flag judged at the daily pass with longitudinal context; "find all instances" is a typed-links COUNT query, never model recall; trend claims must survive an aggregate (candidates-from-summaries, verdicts-from-atoms — the anti-cherry-picking protocol). The model owns wording; never ordering, inclusion, or facts.
- **P8, the fundamental law of LLMs** (Sam's own formulation): quality decays exponentially with nested summaries. Mechanical consequences: compaction depth ≤ 2; every rollup re-derives from atoms (prior summaries are *context, never source* — only trajectory claims may cite them); absolute dates; verbatim quotes for load-bearing facts; re-ground from tier-0 refs before any irreversible action; delta edits, never full-page regeneration.
- **Two-lane scoring** (Sam caught the bug): obligations score by importance × urgency (recency of creation is irrelevant to something due now); background context scores by importance × recency. Cobb-Douglas with floors (his utility intuition; floors prevent a product from zeroing old-but-critical items).
- **Taste is data**: role weights, directives, the purpose contract — all user-set, reaching agents as data. The mirror is the one agent licensed to model taste, and it owns exactly one judgment: how the user is living up to his purpose. It hands taste to no other agent.
- **Security in one breath**: deterministic stops at every boundary; probabilistic layers operate only inside them. OS users are trust tiers; clearance keys on `session_user`; text never escalates privilege; taste writes additionally require the **intent binding** (verbatim-in-raw or edge read-back-confirm — a channel proof is not an intent proof; this closed the deepest red-team finding); capability is issued, never declared; one sender (the edge), destinations hardwired; approvals bind to a server-rendered what-will-execute view, never an agent summary; `suspected_injection` content renders inert everywhere. Assume workers get prompt-injected — intake is adversary-writable by construction.
- **Reliability is absolute for reminders** (P6): LLMs never in a reminder's critical path; degraded-mode delivery (if the model step fails, the deterministic skeleton still sends); watchdog + external dead-man (the alarm must not depend on the alarm channel); critical components never auto-disable; leases on every claim; the system must survive three weeks of total neglect and recover with one rollup, no cleanup project (neglect mode).
- **The wiki is the biography**, not a DB mirror — a wikipedia of the noteworthy, eleven fixed chapters, page bar two-sided (useful to Sam-in-6-months for journaling joy, OR to his agents for a future query). The owner's reading appetite is the scarce resource: pages need a chapter + a read-moment at creation; page count grows sublinearly with atoms. Fabricated citations are the #1 documented AI-wiki defect → lint checks citations exist, the verifier step (fresh context, never the author) checks they support claims; human corrections are immutable spans.
- **Gardener minimax (P9)**: every gardener run is evidence of an upstream design gap — the design denies gardeners work (constraints, idempotence, templated low-signal atoms); the system ensures they run anyway. A shrinking gardener workload is health.
- **Nothing scattered (P10)**: one parameters registry (core/outer rings); one folder per agent (`core/agents/<id>/` with prompt.md + context.md declaring its deterministic context pulls). Tweaking is editing a folder.
- **Staged hardening**: two OS users at P1, full tiers + pf + Tailscale at P3 — security ceremony arrives with its load, because Ring-0 setup burden is the most likely project-killer (the UX rings audit's "sins list" thinking).

## Pitfalls future agents must not reintroduce

1. Building harness machinery (loops, routers, schedulers, message gateways) — the failure that killed both predecessors. The one permitted resident besides the panel is the edge; the orchestrator may run resident only as a configured occupant of its slot.
2. LLM taste leaking into ordering, inclusion, importance, or headlines. The scaffold computes; the model phrases.
3. Summary-of-summary chains, relative dates, paraphrased commitments. P8 is law.
4. Anecdote-driven assessments. Aggregate first, cite both the number and the atoms, label impressions as impressions.
5. Speculative structure: new tables, vocab kinds, parameters, or pages built for imagined volume. Grow by promotion on observed need; shrink by demotion. When the over-engineering instinct fires, it's probably right.
6. Treating channel proof as intent proof anywhere new. Any new write path that could encode taste must carry the intent binding.
7. Mirroring data that has an authoritative home (gcal, Gmail, chat.db). Pointers + compactions; `fetch_ref` makes dereference one cheap call.
8. Forgetting third parties: ward members and founders never consented — sensitivity defaults by role context, pastoral content stays out of low-clearance packets structurally.
